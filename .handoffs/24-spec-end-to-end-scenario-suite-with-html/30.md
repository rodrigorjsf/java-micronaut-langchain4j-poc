## What was built
- The loader rejects an invalid row. The error names the file, the row id (or its position when the id is missing) and the reason. It checks for: unknown kind or source; missing or empty `dependsOn`, `domains` or `turns`; no expected outcome; a duplicate id; a `multi-turn` row with fewer than 2 turns; and `kind: upstream-failure` if and only if `upstream` is set (the rule from the #30 comment).
- Three system properties narrow `ScenarioSuiteEval`, and they combine with AND:
  - `-Dscenario.domain=<d>`
  - `-Dscenario.ids=<a,b>`
  - `-Dscenario.changedSince=<ref>` (diff mode)

  An unknown domain or id is refused. A selection that matches nothing aborts the eval as skipped.
- Diff mode fingerprints every artifact at the ref and in the working tree (uncommitted and untracked files count). It then selects the rows whose `dependsOn` names a changed artifact. The artifact kinds are skill, tool, system-prompt section, catalogue key and sub-agent.
- `eval-report.html` now contains:
  - a Selection line;
  - a "Coverage per domain" table against the floor (≥2 happy, ≥3 named bad paths, 1 multi-turn if the domain is stateful), covering the whole dataset;
  - "Uncovered artifacts";
  - "Unknown dependencies" (`dependsOn` entries that name nothing).

## Decisions & deviations
- **The coverage floor is reported, never gated.** The ticket says "dataset is validated (… coverage floor …)". Gating it now would fail every load and every eval, because the committed dataset has 1 happy weather row. The comment on #47 (the dataset ticket) asks whether it should gate once every domain meets it. `docs/05-evaluation.md` links #47.
- The stateful domains are declared in `src/test/resources/evals/stateful-domains.json` and hold only `["weather"]`. I chose that list. The skill (#32) and the dataset ticket (#47) should settle it.
- The named bad paths are exactly the five from spec story 5: `missing-info`, `out-of-territory`, `upstream-failure`, `injection` and `ambiguous`. `out-of-scope`, `cross-domain` and `multi-turn` count neither as happy nor as bad.
- Artifact identifiers are bare names, matching the existing rows. System-prompt sections are `system-prompt#<heading-slug>`: role, non-negotiable-rules, skills, how-to-answer, arithmetic (`prompt/CALCULATION.md`) and voice (`voice/VOICE.md`). Two artifacts sharing an id fail the scan.
- How each fingerprint is built:
  - A tool is its `@Tool`…`{` header plus the code its class shares. So editing a description selects that tool only, while editing shared code selects every tool of the class. This is deliberate over-selection.
  - A catalogue key is its parsed YAML value, so a comment edit changes nothing.
  - A sub-agent is its whole file.
  - A skill is every file in its directory.
- The property names follow the ticket (`scenario.*`). The existing repetitions property is `scenarios.repetitions` (plural), a naming mismatch left as it was.
- Diff mode compares the ref against the working tree, not against `HEAD`, so that uncommitted edits count. It uses `git diff --relative --no-renames` plus untracked files.
- A default-build test asserts that every committed `dependsOn` names a real artifact. The loader itself does not refuse unknown ones, because it needs no repository scan.

## Code review
Standards axis:
- Fixed: a `@Tool` without a public method was credited to the next tool, and could throw from overlapping spans. It now fails loudly.
- Fixed: duplicate ids silently overwrote each other. They now fail loudly.
- Fixed: only the first `@Agent` of a file was inventoried.
- Fixed: git paths were relative to the top level. They are now relative to `repositoryRoot` (`--relative`).
- Fixed: `KINDS` repeated the bad-path literals. It is now built as a union.
- Fixed: duplicated setup. Added `ScenarioCoverage.empty()`, `ScenarioSelection.everything()` and `ArtifactInventory.ofWorkingTree`.
- Fixed: fully qualified names inline beside imports.
- Fixed: `ok` renamed to `runOrThrow`.
- Fixed: glossary drift. `CONTEXT.md` now has named bad paths, Artifact, uncovered and diff mode.
- Dismissed: static I/O helpers (`GitChanges`, `readWorkingTree`, `loadStatefulDomains`) against the java-concurrency-static rule. This is test-only harness code, and it follows the precedent `ScenarioDataset.load`. The rule's reasons (proxies, spans) don't apply. P2.
- Dismissed: String kind/source instead of enums. Existing row types use Strings, and the report prints them.
- Dismissed: null-means-unset in `ScenarioSelection`. It is a small record, and the nulls are documented.
- Dismissed: moving the Kind label onto the enum. There is only one switch.

Spec axis:
- Floor not gated: dismissed and handed to #47 (see Decisions).
- Unknown `dependsOn` accepted by the loader: dismissed, because the committed-dataset test guards it.
- Scope extras (duplicate ids, source enum, multi-turn ≥2 turns, the Selection line, Unknown dependencies): kept. Each follows from #24's row shape, or prevents a silent no-op.
- The regex-fragility risk was fixed by failing loudly.
