## What was built
- A scenario row can now carry `expect.answer`: `{language, contains[], grounded[]}`.
- The runner adds a second, deterministic layer of checks after the trajectory checks:
  - `no link outside the catalogue` runs on every answer, whether or not the row asks for it. It uses the app's own `LinkPolicy` bean.
  - `language` supports `pt-BR` and `en`, using triage's `MessageLanguage.detect`.
  - `contains: <text>` is case-insensitive.
  - `grounded: <regex>` requires every value the regex captures in the answer to appear in a data-tool result captured in the same run.
- Each check carries a pass/fail and a reason. The report renders all of them, plus a new "Expected answer" row.
- The committed weather row now asserts `language: pt-BR` and a grounded weather-value pattern.

## Decisions & deviations
- **Grounding shape.** A row lists regexes, not values, because the values are live. Group 1 is used when present, otherwise the whole match. A pattern that finds no value in the answer fails ("the row asked for a value").
- **Numbers compare as numbers.** A decimal comma is read, and a tool number that rounds HALF_UP to the answer's precision grounds it ("20 °C" from 19.8).
  - Only standalone numbers count: key fragments (`_2m_`), date parts and exponents don't.
  - Non-numeric values use a case-insensitive substring match.
  - `activate_skill` and `read_skill_resource` results are excluded, because a skill body is instructions, not data.
- **The link check always runs.** It is a universal invariant. It detects `http(s)://host` and markdown `](//host`, the same forms `ExfiltrationGuardrail` treats as links. Bare scheme-less hosts are not checked (dismissed, see review).
- **Language.** The check reuses the production detector through a test-only bridge, `src/test/java/.../triage/AnswerLanguage.java`, so `MessageLanguage` stays package-private. Only `pt-BR` and `en` are supported; any other tag fails with a reason. Known limitation #48.
- **Constructor change.** `ScenarioRunner` now takes a third argument, `ScenarioRunner(URI, RecordingAgentTracer, LinkPolicy)`. Both call sites are updated.
- `Scenario.Expectation` gained an `answer` component, which may be null. `EvalReportRendererTest` was updated to match.
- Row patterns compile with `UNICODE_CHARACTER_CLASS`, so `\s` matches the no-break space models put before units.
- **Risk on the real run.** The weather row is critical, and its grounded pattern requires the real answer to cite at least one value in mm, °C, ° or %. A real answer with no number would fail it.
- **Docs.** In `docs/05-evaluation.md`, "End-to-end scenarios" now has a check-layer table, a grounding-by-example table and an updated Mermaid diagram.

## Code review
Spec axis:
- Fixed: the runner pass-path now explicitly asserts that a grounded check exists and passes. It was already covered by `allSatisfy`.
- Filed as #49: rounding tolerance grounds invented integers within ±0.5 of any captured number.
- Filed as #49: thousands separators are misread.
- Filed as #48: Spanish reads as pt-BR.
- Dismissed: bare scheme-less hosts. They match the guardrail's definition of a link, and `LinkPolicy` scrubs tool results the same way.
- Dismissed as scope creep: rounding, NOT_DATA, and the always-on link check. Each is defensible and documented.

Standards axis:
- Fixed: date parts and exponents were read as numbers. `NUMBER` now excludes them.
- Fixed: the no-break space. Row patterns use Unicode classes.
- Fixed: the duplicated case-insensitive contains. It is now a `contains` helper plus `containsIgnoringCase`.
- Filed as #49: thousands separators.
- Dismissed: host extraction duplicates `LinkPolicy`'s private patterns. Sharing them would change production API for test code. The allow-list itself stays the single injected object.
- Dismissed: `language` as a raw String. Row validation belongs to the dataset-validation ticket.
- Dismissed: the `AnswerLanguage` middle man. It is intentional and documented.
- Dismissed: an unmatched optional group falls back to the whole match. That is minor and fails safe.
