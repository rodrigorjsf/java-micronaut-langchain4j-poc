## Decisions & deviations
- I chose `health-and-food`, not the largest skill (`network-and-identity`). It has the clearest scope cut: a packaged-food path versus a recipe path. The ticket asks for "at least one" skill. The rest are filed as #60.
- Brewery reading rules stay in the body. They are five lines, and a reference would cost a round trip for less text than its pointer row.
- The "once per conversation" wording limits the extra round trip against `max-tool-round-trips: 6`. It is not measured; see #60.
- `SkillCatalog.SKILLS_DIRECTORY` went from private to package-private so the test uses the same constant.

## Notes for dependent tickets
- The pattern for a runtime reference is a third column in the body's entry table naming `read_skill_resource("<skill>", "references/<scope>.md")`. `SkillResourceTest.skillBodiesAndResourcesAgree` enforces the body/resource agreement in both directions for every runtime skill. A new resource that no body names fails the build.
- `ArtifactInventory` already fingerprints every file under a skill directory, so an edit to a reference selects that skill's scenarios.
- `AnswerCheck` already treats `read_skill_resource` results as non-data for grounding.
