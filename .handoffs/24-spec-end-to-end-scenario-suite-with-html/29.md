## What was built
- A row with several `turns` runs as one conversation. Turn 1 is sent without a `conversationId`, and every later turn sends back the id the endpoint returned. The model therefore sees earlier turns as memory.
- `ScenarioResult.turns()` holds one `TurnResult` per completed turn: number, message, conversationId, the trajectory of that turn only (sliced from the recording tracer between request and response) and the answer.
- Checks can target one turn through `expect.turns: [{turn, trajectory, answer}]` (1-based). Their names are prefixed `turn N: ...`. Grounding for turn N searches the tool results of turns 1..N. A row that targets a turn the scenario does not have gets a failing `turn N` check.
- The report summary has a new line, "Coverage per domain". A scenario counts toward every domain it names.
- A multi-turn repetition renders each turn in order: message, conversation id, outcome, activations, tool calls, answer. A scenario's expected per-turn checks appear as "Expected at turn N" rows.
- A run that stops partway (HTTP 500, or a rate limit on turn N) keeps the turns that finished, and its failed check names the turn where it stopped.
- `docs/05-evaluation.md` has a new section, "Multi-turn and cross-domain rows", and the Mermaid diagram now shows the per-turn loop.

## Acceptance criteria
- [x] `turns[]` with more than one entry reuses one conversation id, and checks can target a specific turn. Proved by `ScenarioRunnerTest.everyTurnSharesOneConversation` (same id, and the second model request contains turn 1's text) and `checksCanTargetOneTurn`.
- [x] A scenario with two `domains[]` counts toward both in coverage. Proved by `EvalReportRendererTest.aCrossDomainScenarioCountsTowardBothDomains`, plus `ScenarioDatasetTest.loadsAMultiTurnCrossDomainRow` for the JSON shape.

## Decisions & deviations
- `Expectation` gained a third component, `turns`. A 2-arg constructor was kept so existing call sites compile. `ScenarioResult` gained `turns` as its 10th component, and the 8-arg constructor was kept (it sets turns empty and not skipped).
- Scenario-wide `expect.trajectory` and `expect.answer` keep their meaning: tools from any turn, and the last turn's outcome and answer.
- Per-turn answer checks run only when a turn declares `answer`. On earlier turns without an answer expectation, the always-on link check does not run. It still runs on the last answer.
- Coverage is a single count per domain, computed inline in `EvalReportRenderer.coverage`. The coverage floor, the happy/bad breakdown and uncovered artifacts belong to #30.
- No committed multi-turn or cross-domain row was added to `weather.json`. Dataset authoring is the job of the #32 skill and the first-dataset pass, so the capability is proven with rows built in the tests.
- Multi-turn layout is chosen from `scenario.turns().size() > 1`, not from the number of completed turns, so an interrupted run still shows its turns.
