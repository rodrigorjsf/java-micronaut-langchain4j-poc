## What was built
- `.claude/skills/progressive-tool-disclosure/SKILL.md` no longer says that skills and tool search "do not compose". A new section, "Skills and tool search coexist — as a partition", has a table covering four kinds of tool: skill-scoped tools are never searchable; regular tools, meaning `.tools(...)` or a non-dynamic provider, are searchable; `activate_skill` and `read_skill_resource` are `ALWAYS_VISIBLE`, and `read_skill_resource` exists only when some skill has resources. It explains both code cases. When some skill has tools, the provider is dynamic and gets refreshed after the search filter. When no skill has tools, the provider is static, and the management tools survive the filter only because they are `ALWAYS_VISIBLE`. "Choose skills or search" is now a placement rule, with a warning about a tool placed on the wrong side.
- In the diagram, `read_skill_resource` is marked "only when at least one skill ships a resource file", and a skill's own tools are marked "only after activation".
- The threshold is now ten tools everywhere. A new subsection, "The threshold: ten tools", cites Anthropic's advanced-tool-use article (2025-11-24) with verbatim quotes and its measured figures (~77K to ~8.7K tokens, an 85% cut; MCP-eval accuracy 49% to 74% on Opus 4 and 79.5% to 88.1% on Opus 4.5). The figures are labelled as measurements of Anthropic's own tool.
- The same threshold and coexistence wording now appear in the `agentic-tool-boundary` description, `tool-search-rollout/SKILL.md`, `docs/06-skills.md` (the prose, the table rows and the mermaid edge labels), `README.md`, and the `SkillCatalog` javadoc. ADR 0005 reason 1 is marked disputed with a pointer to #54.
