## Decisions & deviations
- Replaced `gen_ai.system` outright rather than dual-emitting: nothing in the repo (collector, dashboards, alert rules, scripts) reads it, and Langfuse maps neither key for this scope.
- What Langfuse reads was checked in its source at tags v4.16.0 and v3.80.0: `gen_ai.system` is read only in the Vercel AI SDK scope (`ai`) model parameters and a gemini adapter check for `gcp.vertex.agent`; `gen_ai.provider.name` only to recognise `microsoft.agent_framework`. 3.80.0 reads neither.
- The v4 run used 4.46.0, not the documented 4.16.0: the repo compose tag `langfuse:4` floats and pulled 4.46.0. 4.16.0 is covered by the source reading only, and docs/08 says so in the row.
- Port 3000 was taken by an unrelated local Langfuse (`langfuse-mcp-it`, 4.46.0); the repo stack was started with a scratchpad compose override mapping `langfuse-web` to 3003 (`ports: !override`). Both repo stacks were stopped afterwards, as they had been before.
- Provider value keeps the LangChain4j spelling (not registry `gcp.gen_ai`), as docs/07 already decided.
- `GenAiAttributes.SYSTEM` renamed to `PROVIDER_NAME`; `Observation.genAi` parameter renamed `providerName`.
